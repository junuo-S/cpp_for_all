# 01 C++11现代语法特性

C++11 是 C++ 语言发展史上最重要的一次革新。它在语法层面引入了大量现代化特性，让 C++ 代码变得更安全、更简洁、更易读。本篇文章将集中介绍 C++11 中那些"小而美"的语法改进——它们虽然各自独立，却共同构成了现代 C++ 编程的基础设施。

---

## 一、nullptr：类型安全的空指针

### 1.1 旧时代的 NULL 之痛

在 C++11 之前，我们通常用 `NULL` 或字面量 `0` 来表示空指针：

```cpp
int* p1 = NULL;   // NULL 实际上是宏 #define NULL 0
int* p2 = 0;      // 字面量 0 也可以表示空指针
```

这看似没有问题，但在函数重载时就会暴露缺陷：

```cpp
#include <iostream>
using namespace std;

void Foo(int n) {
    cout << "Foo(int): " << n << endl;
}

void Foo(int* p) {
    cout << "Foo(int*): " << p << endl;
}

int main() {
    Foo(0);      // 调用 Foo(int)，符合预期
    Foo(NULL);   // 期望调用 Foo(int*)，实际调用 Foo(int)！

    return 0;
}
```

`NULL` 在大多数编译器中被定义为整数 `0`，因此 `Foo(NULL)` 会匹配 `Foo(int)` 而非 `Foo(int*)`。这完全违背了程序员的意图。

### 1.2 nullptr 的引入

C++11 引入了关键字 `nullptr`，它是一个**纯右值**，类型为 `std::nullptr_t`，可以隐式转换为任何指针类型，但**不会**隐式转换为整数类型：

```cpp
#include <iostream>
using namespace std;

void Foo(int n) {
    cout << "Foo(int): " << n << endl;
}

void Foo(int* p) {
    cout << "Foo(int*): " << p << endl;
}

int main() {
    Foo(nullptr);  // 正确调用 Foo(int*)

    int* p = nullptr;       // 空指针
    double* d = nullptr;    // 同样适用
    bool b = (p == nullptr); // true

    // int n = nullptr;     // 编译错误！不能转换为 int

    return 0;
}
```

### 1.3 最佳实践

| 场景 | 旧写法 | 现代写法 |
|------|--------|----------|
| 初始化空指针 | `int* p = NULL;` | `int* p = nullptr;` |
| 判断空指针 | `if (p == NULL)` | `if (p == nullptr)` |
| 函数传空指针 | `Foo(NULL)` | `Foo(nullptr)` |

> **建议**：在所有需要表示空指针的场合，一律使用 `nullptr`，彻底告别 `NULL` 和字面量 `0`。

## 二、统一初始化与 std::initializer_list

### 2.1 初始化方式的混乱

C++11 之前，变量的初始化方式五花八门：

```cpp
int a = 10;          // 拷贝初始化
int b(20);           // 直接初始化
int arr[] = {1,2,3}; // 数组初始化
int* p = new int(5); // 堆上初始化
struct Point { int x, y; };
Point pt = {1, 2};   // 聚合初始化（仅限 POD）
```

不同的类型、不同的场景需要不同的初始化语法，增加了学习成本和出错概率。

### 2.2 花括号统一初始化

C++11 引入了**花括号初始化**（Brace Initialization），用 `{}` 统一了几乎所有初始化场景：

```cpp
#include <iostream>
#include <vector>
#include <string>
using namespace std;

struct Point {
    int x, y;
};

int main() {
    int a{10};              // 基本类型
    int b = {20};           // 也可以加等号
    int arr[]{1, 2, 3, 4}; // 数组
    Point pt{3, 4};        // 结构体
    vector<int> v{1, 2, 3, 4, 5};  // 容器
    string s{"hello"};     // 字符串

    int* p = new int{99};  // 堆上

    cout << a << " " << b << endl;
    cout << pt.x << ", " << pt.y << endl;
    for (int val : v) cout << val << " ";
    cout << endl;

    return 0;
}
```

### 2.3 窄化转换的防护

花括号初始化有一个重要优势：**禁止窄化转换**（Narrowing Conversion）。如果初始化值无法无损地存入目标类型，编译器会报错：

```cpp
int main() {
    int x{3.14};      // 编译错误！double → int 是窄化转换
    int y = 3.14;     // 旧写法：仅警告，不报错（隐式截断）

    char c{256};      // 编译错误！超出 char 范围
    char d = 256;     // 旧写法：静默截断

    return 0;
}
```

这让许多隐蔽的精度丢失 bug 在编译期就被拦截。

### 2.4 std::initializer_list

当你用花括号传入一组值时，编译器实际上构造了一个 `std::initializer_list<T>` 对象。你可以让自己的类也支持这种初始化方式：

```cpp
#include <iostream>
#include <initializer_list>
using namespace std;

class MyContainer {
private:
    int data[100];
    int size;

public:
    MyContainer(initializer_list<int> il) {
        size = 0;
        for (auto val : il) {
            data[size++] = val;
        }
    }

    void Print() const {
        cout << "[";
        for (int i = 0; i < size; ++i) {
            cout << data[i];
            if (i < size - 1) cout << ", ";
        }
        cout << "]" << endl;
    }
};

int main() {
    MyContainer c{10, 20, 30, 40, 50};
    c.Print();  // [10, 20, 30, 40, 50]

    return 0;
}
```

> **注意**：如果一个类同时有接受 `initializer_list` 的构造函数和其他构造函数，花括号初始化会**优先**匹配 `initializer_list` 版本。

## 三、auto 与 decltype 自动类型推导

### 3.1 auto 的基本用法

C++11 赋予了 `auto` 全新的含义：让编译器根据初始化表达式**自动推导**变量的类型。

```cpp
#include <iostream>
#include <vector>
#include <string>
using namespace std;

int main() {
    auto x = 42;          // int
    auto pi = 3.14;       // double
    auto name = string("C++");  // string
    auto flag = true;     // bool

    vector<int> v{1, 2, 3};
    auto it = v.begin();  // vector<int>::iterator —— 不用写冗长的类型名！

    cout << x << " " << pi << " " << name << " " << flag << endl;
    cout << *it << endl;

    return 0;
}
```

`auto` 最大的价值在于**简化冗长的类型声明**，尤其在迭代器、Lambda、模板编程中效果显著。

### 3.2 auto 的推导规则

`auto` 推导时会**丢弃顶层 const 和引用**（除非你显式写出）：

```cpp
int main() {
    const int cx = 100;
    auto a = cx;       // int（顶层 const 被丢弃）
    auto& b = cx;      // const int&（显式引用保留 const）
    const auto c = cx; // const int（显式加回 const）

    int x = 10;
    int& rx = x;
    auto d = rx;       // int（引用被丢弃，得到的是值的拷贝）
    auto& e = rx;      // int&（显式保留引用）

    return 0;
}
```

### 3.3 decltype：获取表达式的类型

`decltype` 可以在**不求值**的情况下获取一个表达式的声明类型：

```cpp
#include <iostream>
using namespace std;

int main() {
    int x = 42;
    decltype(x) y = 100;    // int（与 x 同类型）
    decltype(x + 1) z = 0;   // int（表达式 x+1 的类型）
    decltype((x)) ref = x;  // int&（加括号变成左值表达式，推导出引用）

    cout << y << " " << z << " " << ref << endl;

    return 0;
}
```

`decltype` 的推导规则：

| 表达式形式 | 推导结果 |
|-----------|---------|
| `decltype(expr)`，expr 是变量名 | 该变量的声明类型 |
| `decltype(expr)`，expr 是函数调用 | 函数返回类型 |
| `decltype((expr))`，加括号 | 若 expr 是左值，结果为 `T&` |
| `decltype(expr)`，expr 是纯右值 | 值类型 `T` |

### 3.4 返回类型后置语法

当函数返回类型依赖于参数类型时，C++11 提供了**尾置返回类型**（Trailing Return Type）：

```cpp
#include <iostream>
using namespace std;

// 返回类型取决于 a + b 的类型
template <typename T, typename U>
auto Add(T a, U b) -> decltype(a + b) {
    return a + b;
}

int main() {
    auto r1 = Add(1, 2);       // int
    auto r2 = Add(1, 3.14);    // double
    auto r3 = Add(1.5f, 2.5);  // double

    cout << r1 << " " << r2 << " " << r3 << endl;

    return 0;
}
```

> 在 C++14 中，返回类型推导进一步简化，可以省略 `-> decltype(...)` 部分，编译器自动推导返回类型。

## 四、constexpr 常量表达式

### 4.1 编译期计算的需求

有些值必须在编译期确定，例如数组长度、模板非类型参数、枚举值等。C++11 之前我们用 `const` 或宏：

```cpp
const int SIZE = 10;       // 编译器"可能"在编译期确定
#define MAX_SIZE 100       // 宏：无类型检查，无作用域
```

但 `const` 并不保证编译期求值——如果初始化值来自运行时输入，`const` 变量就只是"只读变量"而非"编译期常量"。

### 4.2 constexpr 变量

`constexpr` 明确告诉编译器：**这个值必须在编译期确定**。

```cpp
#include <iostream>
using namespace std;

int main() {
    constexpr int SIZE = 10;        // 编译期常量
    int arr[SIZE];                  // 合法：数组长度在编译期已知

    // int n;
    // cin >> n;
    // constexpr int BAD = n;       // 编译错误！n 不是编译期常量

    constexpr double PI = 3.14159265358979;
    constexpr double AREA_FACTOR = PI * 2;  // 编译期计算

    cout << SIZE << " " << AREA_FACTOR << endl;

    return 0;
}
```

### 4.3 constexpr 函数

`constexpr` 还可以修饰函数，表示该函数**有可能**在编译期求值（如果所有实参都是编译期常量）：

```cpp
#include <iostream>
using namespace std;

// C++11 要求：函数体只能有一条 return 语句
constexpr int Factorial(int n) {
    return (n <= 1) ? 1 : n * Factorial(n - 1);
}

int main() {
    constexpr int val = Factorial(5);  // 编译期计算：120
    int arr[val];                      // 合法

    int runtime_n;
    cin >> runtime_n;
    int result = Factorial(runtime_n); // 运行时计算：退化为普通函数调用

    cout << val << " " << result << endl;

    return 0;
}
```

> **C++14 放宽了限制**：`constexpr` 函数体可以包含循环、多条语句、局部变量等，不再局限于单条 return。

### 4.4 constexpr 与 const 的对比

| 特性 | `const` | `constexpr` |
|------|---------|-------------|
| 含义 | 只读（运行时可初始化） | 编译期常量 |
| 能否定义数组长度 | 不一定（取决于初始化值） | 一定可以 |
| 能否修饰函数 | 不能 | 可以 |
| 修饰类成员函数 | 表示不修改对象 | 表示可在编译期调用 |

## 五、强类型枚举 enum class

### 5.1 传统枚举的问题

传统 `enum` 存在两个痛点：

```cpp
enum Color { Red, Green, Blue };
enum Fruit { Apple, Orange, Banana };

int main() {
    // 问题 1：枚举值会泄漏到外层作用域
    // int Red = 10;  // 编译错误！Red 已被枚举占用

    // 问题 2：枚举值会隐式转换为 int，可以跨枚举比较
    if (Red == Apple) {  // 编译通过！但语义上毫无意义
        // ...
    }

    return 0;
}
```

### 5.2 enum class 的解决方案

C++11 引入了**强类型枚举**（Scoped Enum）：

```cpp
#include <iostream>
using namespace std;

enum class Color { Red, Green, Blue };
enum class Fruit { Apple, Orange, Banana };

int main() {
    Color c = Color::Red;    // 必须加作用域限定
    Fruit f = Fruit::Apple;

    // if (c == f) {}        // 编译错误！不同类型不可比较
    // int n = c;            // 编译错误！不能隐式转 int

    int n = static_cast<int>(c);  // 必须显式转换
    cout << n << endl;            // 0

    return 0;
}
```

### 5.3 指定底层类型

传统枚举的底层类型由编译器决定，`enum class` 允许你显式指定：

```cpp
enum class Status : uint8_t {
    OK = 0,
    Error = 1,
    Timeout = 2
};
```

这在需要控制枚举占用空间（如网络协议、嵌入式开发）时非常有用。

## 六、范围 for 循环

### 6.1 基本语法

C++11 引入了**范围 for**（Range-based for），让遍历容器变得极其简洁：

```cpp
#include <iostream>
#include <vector>
#include <string>
using namespace std;

int main() {
    vector<int> nums{1, 2, 3, 4, 5};

    // 传统写法
    for (vector<int>::iterator it = nums.begin(); it != nums.end(); ++it) {
        cout << *it << " ";
    }
    cout << endl;

    // 范围 for：简洁明了
    for (int val : nums) {
        cout << val << " ";
    }
    cout << endl;

    // 需要修改元素时，使用引用
    for (int& val : nums) {
        val *= 2;
    }

    // 只读遍历，使用 const 引用（避免拷贝）
    for (const int& val : nums) {
        cout << val << " ";
    }
    cout << endl;

    return 0;
}
```

### 6.2 适用范围

范围 for 可以用于：
- C 风格数组
- `std::initializer_list`
- 任何提供了 `begin()` 和 `end()` 的类型（STL 容器、自定义容器）

```cpp
int main() {
    int arr[] = {10, 20, 30};
    for (int val : arr) {
        cout << val << " ";
    }
    cout << endl;

    string s = "hello";
    for (char ch : s) {
        cout << ch << "-";
    }
    cout << endl;

    return 0;
}
```

### 6.3 与 auto 的配合

范围 for 与 `auto` 是天然搭档，彻底消除了书写复杂类型的负担：

```cpp
#include <map>
#include <iostream>
using namespace std;

int main() {
    map<string, int> scores{{"Alice", 95}, {"Bob", 87}, {"Carol", 92}};

    for (const auto& [name, score] : scores) {  // C++17 结构化绑定
        cout << name << ": " << score << endl;
    }

    // C++11 写法
    for (const auto& pair : scores) {
        cout << pair.first << ": " << pair.second << endl;
    }

    return 0;
}
```

## 七、override / final / =default / =delete

### 7.1 override：显式标记重写

在继承体系中，重写虚函数时如果签名不小心写错，编译器不会报错，而是静默地创建一个新函数：

```cpp
class Base {
public:
    virtual void Process(int x) { }
};

class Derived : public Base {
public:
    // 本意是重写，但参数写成了 double —— 编译器不报错！
    virtual void Process(double x) { }
};
```

C++11 的 `override` 关键字让编译器帮你检查：

```cpp
class Base {
public:
    virtual void Process(int x) { }
    virtual void Display() const { }
};

class Derived : public Base {
public:
    void Process(int x) override { }     // 正确：签名匹配
    // void Process(double x) override {} // 编译错误！基类没有此签名
    // void Display() override {}         // 编译错误！缺少 const
    void Display() const override { }    // 正确
};
```

### 7.2 final：禁止继承或重写

```cpp
class Base final {  // 此类不可被继承
public:
    virtual void Foo() { }
};

// class Derived : public Base { };  // 编译错误！

class A {
public:
    virtual void Bar() final { }  // 此虚函数不可被重写
};

class B : public A {
public:
    // void Bar() override { }  // 编译错误！Bar 已被 final
};
```

### 7.3 =default：显式要求编译器生成默认函数

```cpp
class Widget {
public:
    Widget() = default;                      // 显式使用默认构造函数
    Widget(const Widget&) = default;         // 显式使用默认拷贝构造
    Widget& operator=(const Widget&) = default; // 显式使用默认拷贝赋值
    ~Widget() = default;                     // 显式使用默认析构

    Widget(int x) : value(x) { }            // 自定义构造函数

private:
    int value = 0;
};
```

当你声明了任何构造函数后，编译器不再自动生成默认构造函数。`=default` 让你可以"要回"它。

### 7.4 =delete：禁止特定函数

```cpp
class NonCopyable {
public:
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete;            // 禁止拷贝构造
    NonCopyable& operator=(const NonCopyable&) = delete; // 禁止拷贝赋值
};

class Widget {
public:
    void Process(int x) { }
    void Process(double x) = delete;  // 禁止 double 版本
};

int main() {
    NonCopyable a;
    // NonCopyable b = a;  // 编译错误！拷贝构造已删除

    Widget w;
    w.Process(42);
    // w.Process(3.14);    // 编译错误！double 版本已删除

    return 0;
}
```

> `=delete` 的典型用途：禁止拷贝（如互斥量、独占资源）、禁止隐式类型转换、禁止某些模板实例化。

## 八、static_assert 静态断言

### 8.1 运行时断言的局限

传统的 `assert` 是运行时检查，只有程序执行到那一行才会触发：

```cpp
#include <cassert>

void Process(int* p) {
    assert(p != nullptr);  // 运行时才检查
    // ...
}
```

有些错误完全可以在编译期发现，何必等到运行时？

### 8.2 static_assert 的语法

```cpp
#include <iostream>
#include <type_traits>
using namespace std;

// 编译期检查：确保 int 是 4 字节
static_assert(sizeof(int) == 4, "int must be 4 bytes on this platform");

// 模板中约束类型
template <typename T>
T SafeDivide(T a, T b) {
    static_assert(is_arithmetic<T>::value, "T must be an arithmetic type");
    return a / b;
}

int main() {
    cout << SafeDivide(10, 3) << endl;      // OK
    cout << SafeDivide(10.0, 3.0) << endl;  // OK

    // SafeDivide("a", "b");  // 编译错误！触发 static_assert

    return 0;
}
```

### 8.3 典型应用场景

| 场景 | 示例 |
|------|------|
| 平台兼容性检查 | `static_assert(sizeof(void*) == 8, "64-bit required")` |
| 模板类型约束 | 确保模板参数满足特定条件 |
| 枚举/常量校验 | 确保配置值在合法范围内 |
| 结构体对齐检查 | 确保内存布局符合协议要求 |

> C++17 起，`static_assert` 的消息字符串可以省略：`static_assert(sizeof(int) == 4);`

## 九、总结

### 核心要点回顾

| 特性 | 核心价值 |
|------|---------|
| `nullptr` | 类型安全的空指针，消除 `NULL`/`0` 的歧义 |
| 统一初始化 `{}` | 一种语法适配所有场景，防止窄化转换 |
| `auto` / `decltype` | 自动类型推导，简化冗长类型声明 |
| `constexpr` | 真正的编译期常量与编译期函数 |
| `enum class` | 强类型、有作用域的枚举 |
| 范围 for | 简洁安全的容器遍历 |
| `override` / `final` | 编译期检查虚函数重写，控制继承 |
| `=default` / `=delete` | 精确控制特殊成员函数的生成与禁用 |
| `static_assert` | 编译期断言，尽早暴露错误 |

### 编程建议

1. **全面拥抱 `nullptr`**：任何表示空指针的地方都用 `nullptr`。
2. **优先使用 `{}` 初始化**：除非有明确理由（如避免 `initializer_list` 歧义）。
3. **善用 `auto`**：减少类型噪音，但不要滥用到影响可读性。
4. **用 `constexpr` 替代宏常量**：获得类型安全和作用域控制。
5. **所有虚函数重写都加 `override`**：让编译器帮你捕获签名错误。
6. **用 `=delete` 表达设计意图**：明确告诉使用者哪些操作不被允许。

这些特性看似零散，实则构成了现代 C++ 代码的"基本功"。从下一篇开始，我们将进入模板改进与 Lambda 表达式的世界，看看 C++11 如何让泛型编程和函数式编程变得更加优雅。
