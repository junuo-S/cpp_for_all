# 04 C++11右值引用、移动语义与完美转发

在 C++11 之前，对象的拷贝有时代价高昂——一个包含大量堆内存的 `vector`，仅仅因为函数返回或容器扩容，就要把所有元素深拷贝一遍。C++11 通过引入右值引用和移动语义，让"窃取"即将销毁对象的资源成为可能，从而将许多 O(n) 的拷贝操作降为 O(1) 的指针交换。完美转发则解决了模板代码中值类别丢失的问题，使泛型库能够精确地传递参数。

---

## 一、值类别：理解左值与右值

### 1.1 历史回顾

在 C++11 之前，表达式只分为两类：
- **左值（lvalue）**：有持久地址，可以取地址（`&x` 合法）
- **右值（rvalue）**：没有持久地址，临时的、即将消亡的

```cpp
int x = 42;       // x 是左值，42 是右值
string s = "hi";  // s 是左值，"hi" 产生的临时 string 是右值
x = x + 1;       // x+1 的结果是右值
```

### 1.2 C++11 的五种类别

C++11 细化了值类别体系：

```
        表达式(expr)
       /           \
    glvalue       rvalue
    /    \        /    \
 lvalue  xvalue  xvalue  prvalue
```

| 类别 | 全称 | 特征 | 示例 |
|------|------|------|------|
| lvalue | Left value | 有地址，可取地址 | 变量名、`*p`、`a[i]` |
| prvalue | Pure rvalue | 无地址，初始化值 | 字面量 `42`、`x+y` 的结果 |
| xvalue | eXpiring value | 有地址但即将消亡 | `move(x)`、返回 `T&&` 的函数调用 |
| glvalue | Generalized lvalue | lvalue + xvalue | — |
| rvalue | Right value | xvalue + prvalue | — |

对于日常编程，最重要的区分是：
- **左值**：有名字、有地址、生命周期较长
- **右值**：临时的、即将被销毁的、可以安全"掠夺"其资源

## 二、右值引用 T&&

### 2.1 基本语法

C++11 引入了**右值引用**（Rvalue Reference），用 `T&&` 表示，专门绑定到右值：

```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    string s1 = "hello";
    string& lref = s1;         // 左值引用：绑定左值
    // string& lref2 = "temp"; // 编译错误！左值引用不能绑定右值（非 const）

    const string& clref = "temp";  // const 左值引用可以绑定右值（延长生命周期）

    string&& rref = "world";       // 右值引用：绑定右值
    string&& rref2 = s1 + "!";     // 绑定表达式产生的临时对象

    cout << rref << endl;   // world
    cout << rref2 << endl;  // hello!

    // string&& rref3 = s1;  // 编译错误！右值引用不能绑定左值

    return 0;
}
```

### 2.2 右值引用本身是左值

一个容易混淆的点：**右值引用变量本身是左值**（因为它有名字、有地址）：

```cpp
void Foo(string&& s) {
    // s 是右值引用参数，但 s 本身是左值！
    // Bar(s);    // 如果 Bar 接受 string&&，这里会编译错误
    // Bar(move(s));  // 需要 move 才能继续传递右值性
}
```

### 2.3 绑定规则总结

| 引用类型 | 可绑定 | 不可绑定 |
|---------|--------|---------|
| `T&` | 左值 | 右值 |
| `const T&` | 左值、右值 | — |
| `T&&` | 右值 | 左值 |

## 三、移动构造与移动赋值

### 3.1 拷贝的代价

考虑一个管理动态数组的类：

```cpp
class BigData {
    int* data;
    size_t size;
public:
    // 构造函数
    BigData(size_t n) : size(n), data(new int[n]) {
        cout << "Constructor: allocated " << n << " ints" << endl;
    }

    // 拷贝构造：O(n) 深拷贝
    BigData(const BigData& other) : size(other.size), data(new int[other.size]) {
        copy(other.data, other.data + size, data);
        cout << "Copy Constructor: copied " << size << " ints" << endl;
    }

    ~BigData() { delete[] data; }
};
```

当函数返回一个 `BigData` 对象时，如果编译器无法执行 RVO/NRVO 优化，就会触发深拷贝——即使源对象马上就要被销毁。

### 3.2 移动构造函数

移动构造函数的参数是右值引用，它"窃取"源对象的资源，而非拷贝：

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

class BigData {
    int* data;
    size_t size;
public:
    BigData(size_t n) : size(n), data(new int[n]) {
        cout << "Constructor: allocated " << n << " ints" << endl;
    }

    // 拷贝构造
    BigData(const BigData& other) : size(other.size), data(new int[other.size]) {
        copy(other.data, other.data + size, data);
        cout << "Copy: O(n) deep copy" << endl;
    }

    // 移动构造：O(1) 指针交换
    BigData(BigData&& other) noexcept : data(other.data), size(other.size) {
        other.data = nullptr;  // 将源对象置为有效但空的状态
        other.size = 0;
        cout << "Move: O(1) pointer steal" << endl;
    }

    // 移动赋值
    BigData& operator=(BigData&& other) noexcept {
        if (this != &other) {
            delete[] data;          // 释放自己的旧资源
            data = other.data;      // 窃取对方资源
            size = other.size;
            other.data = nullptr;   // 置空对方
            other.size = 0;
        }
        return *this;
    }

    ~BigData() { delete[] data; }

    size_t Size() const { return size; }
};

BigData CreateData() {
    BigData temp(1000000);  // 分配 100 万个 int
    return temp;            // 移动（或 RVO 优化直接省略）
}

int main() {
    BigData a = CreateData();       // 移动构造（而非拷贝）
    cout << "a.size = " << a.Size() << endl;

    BigData b(10);
    b = move(a);                    // 移动赋值
    cout << "b.size = " << b.Size() << endl;
    cout << "a.size = " << a.Size() << endl;  // 0（资源已被移走）

    return 0;
}
```

### 3.3 std::move 的本质

`std::move` **不移动任何东西**。它只是一个类型转换——将左值强制转换为右值引用，从而使其能匹配移动构造/赋值函数：

```cpp
// std::move 的简化实现
template <typename T>
typename remove_reference<T>::type&& move(T&& t) noexcept {
    return static_cast<typename remove_reference<T>::type&&>(t);
}
```

```cpp
int main() {
    string s1 = "hello world, this is a long string";
    string s2 = move(s1);  // s1 被转为右值 → 触发移动构造

    cout << "s2: " << s2 << endl;  // 拥有原来的内容
    cout << "s1: " << s1 << endl;  // 通常为空（moved-from 状态）

    return 0;
}
```

> **重要**：被 `move` 后的对象处于"有效但未指定"的状态（valid but unspecified）。只能安全地析构或重新赋值，不应依赖其内容。

### 3.4 noexcept 的重要性

移动构造和移动赋值应当标记为 `noexcept`。原因：STL 容器（如 `vector`）在扩容时，只有当移动操作是 `noexcept` 的，才会使用移动；否则为了保证异常安全，会退回到拷贝。

```cpp
// 没有 noexcept → vector 扩容时可能拷贝而非移动
BigData(BigData&& other) : data(other.data), size(other.size) { ... }

// 有 noexcept → vector 扩容时放心使用移动
BigData(BigData&& other) noexcept : data(other.data), size(other.size) { ... }
```

## 四、移动语义在 STL 容器中的体现

### 4.1 vector 扩容

```cpp
#include <iostream>
#include <vector>
#include <string>
using namespace std;

int main() {
    vector<string> v;
    v.reserve(1);  // 先只预留 1 个位置

    string s = "a very long string that definitely uses heap allocation";
    v.push_back(s);            // 拷贝（s 是左值）
    v.push_back(move(s));      // 移动（s 转为右值）
    v.push_back("temp string"); // 移动（字面量构造的临时对象是右值）

    cout << "v[0]: " << v[0] << endl;
    cout << "v[1]: " << v[1] << endl;
    cout << "v[2]: " << v[2] << endl;
    cout << "s after move: '" << s << "'" << endl;  // 通常为空

    return 0;
}
```

### 4.2 函数返回值的优化

```cpp
vector<int> CreateVector() {
    vector<int> v{1, 2, 3, 4, 5};
    return v;  // NRVO：编译器通常直接在调用者空间构造，无需移动也无需拷贝
}

int main() {
    vector<int> result = CreateVector();  // 大概率零开销（NRVO）
    return 0;
}
```

> 即使 NRVO 未生效，返回值也会自动被视为右值，触发移动构造。不要画蛇添足地写 `return move(v);`——这反而会阻止 NRVO。

## 五、万能引用与引用折叠

### 5.1 万能引用（Universal Reference）

当 `T&&` 出现在**模板参数推导**的上下文中时，它不再是单纯的右值引用，而是**万能引用**（也叫转发引用 Forwarding Reference）——既能绑定左值，也能绑定右值：

```cpp
template <typename T>
void Wrapper(T&& arg) {  // T&& 在此是万能引用
    // arg 可以绑定左值，也可以绑定右值
}

int main() {
    int x = 42;
    Wrapper(x);   // OK：T 推导为 int&，参数为 int& && → int&
    Wrapper(42);  // OK：T 推导为 int，参数为 int&&

    return 0;
}
```

万能引用的识别条件（缺一不可）：
1. 形式必须是 `T&&`（精确匹配，`const T&&` 不算）
2. `T` 必须是需要推导的模板参数

### 5.2 引用折叠规则

当出现"引用的引用"时，C++ 按以下规则折叠：

| 组合 | 折叠结果 |
|------|---------|
| `T& &` | `T&` |
| `T& &&` | `T&` |
| `T&& &` | `T&` |
| `T&& &&` | `T&&` |

简记：**只要有一个左值引用 `&`，结果就是左值引用。**

这就是万能引用的工作原理：
- 传入左值 `x` → `T` 推导为 `int&` → 参数类型 `int& &&` → 折叠为 `int&`
- 传入右值 `42` → `T` 推导为 `int` → 参数类型 `int&&`

## 六、完美转发与 std::forward

### 6.1 问题：值类别的丢失

在模板函数内部，无论参数原来是左值还是右值，一旦有了名字，它就变成了左值：

```cpp
template <typename T>
void Relay(T&& arg) {
    // arg 有名字 → 是左值
    // 如果直接传给 Process，无论原来是什么，都会匹配左值版本
    Process(arg);  // 总是调用 Process(const T&) 或 Process(T&)
}
```

### 6.2 std::forward 的解决方案

`std::forward<T>` 根据模板参数 `T` 的推导结果，有条件地将参数转换回右值：

```cpp
#include <iostream>
#include <string>
using namespace std;

void Process(const string& s) {
    cout << "Process(const string&): copy" << endl;
}

void Process(string&& s) {
    cout << "Process(string&&): move" << endl;
}

template <typename T>
void PerfectRelay(T&& arg) {
    Process(forward<T>(arg));  // 完美转发：保持原始值类别
}

int main() {
    string s = "hello";

    PerfectRelay(s);               // s 是左值 → 调用 Process(const string&)
    PerfectRelay(string("temp"));  // 临时对象是右值 → 调用 Process(string&&)
    PerfectRelay(move(s));         // move 产生右值 → 调用 Process(string&&)

    return 0;
}
// 输出:
// Process(const string&): copy
// Process(string&&): move
// Process(string&&): move
```

### 6.3 完美转发的典型应用

工厂函数、`emplace` 系列、`make_unique` / `make_shared` 的内部实现都依赖完美转发：

```cpp
#include <iostream>
#include <memory>
using namespace std;

class Widget {
    string name;
    int value;
public:
    Widget(const string& n, int v) : name(n), value(v) {
        cout << "Widget(" << name << ", " << value << ") constructed" << endl;
    }
};

// 工厂函数：完美转发参数给构造函数
template <typename T, typename... Args>
unique_ptr<T> Create(Args&&... args) {
    return unique_ptr<T>(new T(forward<Args>(args)...));
}

int main() {
    string name = "Gadget";
    auto w1 = Create<Widget>(name, 42);        // name 以左值传递
    auto w2 = Create<Widget>("Temp", 100);     // "Temp" 以右值传递
    auto w3 = Create<Widget>(move(name), 200); // 移动传递

    return 0;
}
```

## 七、emplace_back 与就地构造

### 7.1 push_back 的额外拷贝

```cpp
#include <vector>
#include <string>
#include <iostream>
using namespace std;

int main() {
    vector<pair<string, int>> v;

    // push_back：先构造临时对象，再移动/拷贝进容器
    v.push_back(make_pair(string("Alice"), 95));
    v.push_back(pair<string, int>("Bob", 87));  // 构造临时 pair → 移动入容器

    return 0;
}
```

### 7.2 emplace_back 的就地构造

`emplace_back` 将参数**完美转发**给元素的构造函数，直接在容器内存中构造对象，省去临时对象的创建和移动：

```cpp
int main() {
    vector<pair<string, int>> v;

    // emplace_back：直接在容器内存中调用 pair 的构造函数
    v.emplace_back("Alice", 95);   // 无临时对象
    v.emplace_back("Bob", 87);     // 无临时对象

    for (const auto& [name, score] : v) {
        cout << name << ": " << score << endl;
    }

    return 0;
}
```

### 7.3 性能对比

| 操作 | `push_back` | `emplace_back` |
|------|------------|----------------|
| 参数 | 一个完整的对象（或可转换为对象的值） | 构造函数的参数列表 |
| 过程 | 构造临时对象 → 移动/拷贝入容器 | 直接在容器内存中构造 |
| 临时对象 | 有 | 无 |
| 适用场景 | 已有对象要放入容器 | 用参数直接构造新元素 |

> STL 容器普遍提供了 `emplace` 系列：`emplace_back`、`emplace_front`、`emplace`（关联容器）、`emplace_hint` 等。

## 八、最佳实践与注意事项

### 8.1 何时使用移动语义

- **类管理堆资源**（指针、文件句柄等）：实现移动构造和移动赋值
- **函数返回大型对象**：依赖 NRVO 或隐式移动，无需手动 `move`
- **向容器添加临时对象**：使用 `move` 或 `emplace`

### 8.2 常见错误

```cpp
// 错误 1：对 const 对象 move（无效，退化为拷贝）
const string cs = "hello";
string s1 = move(cs);  // 调用拷贝构造！const 右值引用匹配 const T&

// 错误 2：return move(x) 阻止 NRVO
vector<int> Foo() {
    vector<int> v{1, 2, 3};
    return move(v);  // 不要这样写！阻止了 NRVO
    // return v;     // 正确：编译器自动优化
}

// 错误 3：move 后继续使用对象
string s2 = "world";
string s3 = move(s2);
cout << s2.size() << endl;  // 合法但无意义：moved-from 状态值不确定（多数实现中为 0）
```

### 8.3 Rule of Five

如果一个类需要自定义析构、拷贝构造、拷贝赋值中的任何一个，通常也应该定义移动构造和移动赋值（或显式 `=delete`）：

```cpp
class Resource {
    int* data;
public:
    Resource();
    ~Resource();                              // 1. 析构
    Resource(const Resource&);                // 2. 拷贝构造
    Resource& operator=(const Resource&);     // 3. 拷贝赋值
    Resource(Resource&&) noexcept;            // 4. 移动构造
    Resource& operator=(Resource&&) noexcept; // 5. 移动赋值
};
```

## 九、总结

### 核心要点回顾

| 知识点 | 关键要点 |
|--------|---------|
| 值类别 | lvalue / prvalue / xvalue；左值有地址，右值临时 |
| 右值引用 `T&&` | 绑定右值，延长临时对象生命周期 |
| 移动构造/赋值 | 窃取资源（O(1)），源对象置空 |
| `std::move` | 仅是 `static_cast<T&&>`，不移动任何东西 |
| `noexcept` | 移动操作必须标记，否则容器不敢用移动 |
| 万能引用 | 模板中的 `T&&`，可绑定左值和右值 |
| 引用折叠 | `& &&` → `&`；只有 `&& &&` → `&&` |
| `std::forward` | 按 T 的推导结果有条件地转为右值，实现完美转发 |
| `emplace_back` | 就地构造，避免临时对象 |

### 心智模型

- **左值**是"有身份的"（有地址），**右值**是"可移动的"（即将消亡）
- `move` 是"我承诺不再使用这个对象，你可以拿走它的资源"
- `forward` 是"请保持这个参数原来的身份（左值/右值）传递下去"

移动语义和完美转发是 C++11 性能优化的基石，也是理解智能指针、容器操作、异步编程的底层基础。下一篇，我们将进入 C++11 多线程编程的世界。
