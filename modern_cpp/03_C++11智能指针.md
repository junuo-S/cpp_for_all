# 03 C++11智能指针

手动管理堆内存是 C++ 程序员最大的心智负担之一。忘记 `delete` 导致内存泄漏，重复 `delete` 导致未定义行为，异常路径跳过 `delete` 导致资源泄露——这些问题在大型项目中层出不穷。C++11 引入的智能指针，基于 RAII 思想，将资源的生命周期绑定到对象的生命周期上，从根本上消除了这类错误。

---

## 一、手动内存管理的痛点与 RAII 思想

### 1.1 手动管理的典型问题

```cpp
#include <iostream>
using namespace std;

class Resource {
public:
    Resource() { cout << "Resource acquired" << endl; }
    ~Resource() { cout << "Resource released" << endl; }
    void Use() { cout << "Using resource" << endl; }
};

void Problematic() {
    Resource* r = new Resource();

    r->Use();

    // 问题 1：如果这里抛出异常，下面的 delete 永远不会执行
    // throw runtime_error("something went wrong");

    // 问题 2：如果函数有多个 return 分支，容易漏掉 delete
    if (true) {
        return;  // 提前返回，忘记 delete → 内存泄漏！
    }

    delete r;  // 可能永远执行不到
}
```

即使程序员非常小心，在复杂的控制流（多分支、异常、循环）中，保证每条路径都正确释放资源也是极其困难的。

### 1.2 RAII：资源获取即初始化

RAII（Resource Acquisition Is Initialization）是 C++ 最重要的编程惯用法：

- **构造时获取资源**（打开文件、分配内存、加锁）
- **析构时释放资源**（关闭文件、释放内存、解锁）
- 利用 C++ 的确定性析构（对象离开作用域时自动调用析构函数）保证资源一定被释放

智能指针就是 RAII 在堆内存管理上的直接应用：把裸指针包装在栈对象中，析构时自动 `delete`。

```cpp
void Safe() {
    // 智能指针在栈上，离开作用域自动析构 → 自动 delete 堆对象
    unique_ptr<Resource> r(new Resource());
    r->Use();

    if (true) {
        return;  // 安全！r 的析构函数会自动被调用
    }
}   // 正常退出时，r 的析构函数也会被调用
```

## 二、std::unique_ptr

### 2.1 独占语义

`unique_ptr` 表达的是**独占所有权**：同一时刻只能有一个 `unique_ptr` 指向某个对象。它不能被拷贝，只能被**移动**。

```cpp
#include <iostream>
#include <memory>
using namespace std;

class Widget {
    int id;
public:
    Widget(int i) : id(i) { cout << "Widget " << id << " created" << endl; }
    ~Widget() { cout << "Widget " << id << " destroyed" << endl; }
    void Show() const { cout << "Widget " << id << endl; }
};

int main() {
    unique_ptr<Widget> p1(new Widget(1));
    p1->Show();

    // unique_ptr<Widget> p2 = p1;  // 编译错误！不可拷贝

    unique_ptr<Widget> p2 = move(p1);  // 移动所有权
    // p1 现在是 nullptr
    if (!p1) cout << "p1 is empty" << endl;
    p2->Show();

    return 0;
}
// 输出:
// Widget 1 created
// Widget 1
// p1 is empty
// Widget 1
// Widget 1 destroyed
```

### 2.2 make_unique（C++14）

C++14 引入了 `make_unique`，提供更安全、更简洁的创建方式：

```cpp
int main() {
    // C++11 写法
    unique_ptr<Widget> p1(new Widget(1));

    // C++14 推荐写法
    auto p2 = make_unique<Widget>(2);

    // 数组版本
    auto arr = make_unique<int[]>(100);
    arr[0] = 42;

    return 0;
}
```

`make_unique` 的优势：
- 代码更简洁，无需重复写类型
- 异常安全（避免 `new` 和 `unique_ptr` 构造之间的异常窗口）

### 2.3 工厂模式中的应用

`unique_ptr` 天然适合工厂函数——函数创建对象，将所有权转移给调用者：

```cpp
#include <iostream>
#include <memory>
using namespace std;

class Shape {
public:
    virtual void Draw() const = 0;
    virtual ~Shape() = default;
};

class Circle : public Shape {
public:
    void Draw() const override { cout << "Drawing Circle" << endl; }
};

class Rectangle : public Shape {
public:
    void Draw() const override { cout << "Drawing Rectangle" << endl; }
};

// 工厂函数：返回 unique_ptr，转移所有权
unique_ptr<Shape> CreateShape(const string& type) {
    if (type == "circle") return make_unique<Circle>();
    if (type == "rect")   return make_unique<Rectangle>();
    return nullptr;
}

int main() {
    auto shape = CreateShape("circle");
    if (shape) shape->Draw();

    shape = CreateShape("rect");
    if (shape) shape->Draw();

    return 0;
}
```

### 2.4 自定义删除器

默认情况下 `unique_ptr` 使用 `delete` 释放资源。对于非标准资源（文件句柄、网络连接等），可以自定义删除器：

```cpp
#include <iostream>
#include <memory>
#include <cstdio>
using namespace std;

int main() {
    // 自定义删除器：用 fclose 关闭文件
    FILE* fp = fopen("test.txt", "w");
    if (!fp) {
        cerr << "Failed to open file" << endl;
        return 1;
    }

    unique_ptr<FILE, decltype(&fclose)> file(fp, fclose);

    fprintf(file.get(), "Hello, Smart Pointer!\n");
    // 离开作用域时自动调用 fclose

    return 0;
}
```

### 2.5 释放与重置

```cpp
int main() {
    auto p = make_unique<Widget>(1);

    p.reset();              // 释放当前对象，p 变为 nullptr
    p.reset(new Widget(2)); // 释放旧对象，接管新对象

    Widget* raw = p.release();  // 放弃所有权，返回裸指针（不会 delete）
    // 现在需要手动管理 raw
    delete raw;

    return 0;
}
```

## 三、std::shared_ptr

### 3.1 共享所有权与引用计数

`shared_ptr` 允许多个指针**共享**同一个对象的所有权。内部维护一个引用计数，当最后一个 `shared_ptr` 被销毁时，对象才被释放。

```cpp
#include <iostream>
#include <memory>
using namespace std;

class Data {
    string name;
public:
    Data(const string& n) : name(n) { cout << name << " created" << endl; }
    ~Data() { cout << name << " destroyed" << endl; }
    void Show() const { cout << "Data: " << name << endl; }
};

int main() {
    shared_ptr<Data> p1 = make_shared<Data>("Alpha");
    cout << "引用计数: " << p1.use_count() << endl;  // 1

    {
        shared_ptr<Data> p2 = p1;  // 共享所有权
        cout << "引用计数: " << p1.use_count() << endl;  // 2

        shared_ptr<Data> p3 = p1;
        cout << "引用计数: " << p1.use_count() << endl;  // 3
    }
    // p2, p3 离开作用域，计数减 2

    cout << "引用计数: " << p1.use_count() << endl;  // 1
    p1->Show();

    return 0;
}
// 输出:
// Alpha created
// 引用计数: 1
// 引用计数: 2
// 引用计数: 3
// 引用计数: 1
// Data: Alpha
// Alpha destroyed
```

### 3.2 控制块

每个 `shared_ptr` 管理的对象都关联一个**控制块**（Control Block），其中包含：

- 强引用计数（`shared_ptr` 的数量）
- 弱引用计数（`weak_ptr` 的数量）
- 删除器
- 分配器

```
shared_ptr ──┐
             ├──→ [控制块: strong=2, weak=1] ──→ 实际对象
shared_ptr ──┘
weak_ptr ────────↗
```

### 3.3 make_shared 的优势

```cpp
// 方式 1：两次内存分配（对象 + 控制块分开分配）
shared_ptr<Data> p1(new Data("Beta"));

// 方式 2：一次内存分配（对象和控制块在同一块内存中）
auto p2 = make_shared<Data>("Gamma");
```

`make_shared` 的优势：
- **性能**：只需一次 `new`，减少内存分配开销
- **缓存友好**：对象和控制块相邻，访问局部性好
- **异常安全**：与 `unique_ptr` 的 `make_unique` 同理

### 3.4 别名构造

`shared_ptr` 支持别名构造（Aliasing Constructor）：让一个 `shared_ptr` 指向对象的某个子部分，但共享整个对象的生命周期：

```cpp
struct Node {
    int value;
    int extra;
};

int main() {
    auto node = make_shared<Node>();
    node->value = 42;

    // alias 指向 node->value，但生命周期与 node 绑定
    shared_ptr<int> alias(node, &node->value);

    cout << *alias << endl;  // 42
    // alias 和 node 共享引用计数

    return 0;
}
```

## 四、std::weak_ptr

### 4.1 循环引用问题

`shared_ptr` 的引用计数机制有一个致命弱点——**循环引用**会导致内存泄漏：

```cpp
#include <iostream>
#include <memory>
using namespace std;

struct B;  // 前向声明

struct A {
    shared_ptr<B> b_ptr;
    ~A() { cout << "A destroyed" << endl; }
};

struct B {
    shared_ptr<A> a_ptr;  // 循环引用！
    ~B() { cout << "B destroyed" << endl; }
};

int main() {
    auto a = make_shared<A>();
    auto b = make_shared<B>();

    a->b_ptr = b;  // a 引用 b（b 的计数变为 2）
    b->a_ptr = a;  // b 引用 a（a 的计数变为 2）

    return 0;
    // main 结束：a 和 b 的计数各减 1，变为 1
    // 但谁也不为 0，谁也不会被释放 → 内存泄漏！
    // "A destroyed" 和 "B destroyed" 都不会打印
}
```

### 4.2 weak_ptr 打破循环

`weak_ptr` 是一种**不增加引用计数**的观察者指针，专门用来解决循环引用：

```cpp
struct B;

struct A {
    shared_ptr<B> b_ptr;
    ~A() { cout << "A destroyed" << endl; }
};

struct B {
    weak_ptr<A> a_ptr;  // 改为 weak_ptr，不增加 a 的引用计数
    ~B() { cout << "B destroyed" << endl; }
};

int main() {
    auto a = make_shared<A>();
    auto b = make_shared<B>();

    a->b_ptr = b;
    b->a_ptr = a;  // weak_ptr 不增加计数

    return 0;
    // a 计数归 0 → A destroyed → b 计数归 0 → B destroyed
}
// 输出:
// A destroyed
// B destroyed
```

### 4.3 lock() 安全访问

`weak_ptr` 不能直接解引用（因为对象可能已被释放）。必须先通过 `lock()` 尝试提升为 `shared_ptr`：

```cpp
#include <iostream>
#include <memory>
using namespace std;

int main() {
    weak_ptr<int> weak;

    {
        auto shared = make_shared<int>(42);
        weak = shared;

        // 对象还存活
        if (auto locked = weak.lock()) {
            cout << "值: " << *locked << endl;  // 42
        }
    }
    // shared 已销毁

    // 对象已不存在
    if (auto locked = weak.lock()) {
        cout << *locked << endl;
    } else {
        cout << "对象已释放" << endl;  // 执行这里
    }

    // 也可以用 expired() 检查
    cout << "expired: " << weak.expired() << endl;  // true

    return 0;
}
```

### 4.4 典型应用场景

| 场景 | 说明 |
|------|------|
| 打破循环引用 | 父子关系中，子指向父用 `weak_ptr` |
| 缓存 | 缓存持有 `weak_ptr`，不阻止对象释放 |
| 观察者模式 | 观察者持有被观察者的 `weak_ptr` |
| 避免悬空指针 | 通过 `lock()` 安全检测对象是否存活 |

## 五、三种智能指针对比与选择策略

### 5.1 对比表

| 特性 | `unique_ptr` | `shared_ptr` | `weak_ptr` |
|------|-------------|-------------|-----------|
| 所有权 | 独占 | 共享 | 无（观察者） |
| 可否拷贝 | 不可 | 可以 | 可以 |
| 可否移动 | 可以 | 可以 | 可以 |
| 引用计数 | 无 | 有 | 不增加计数 |
| 开销 | 与裸指针相同 | 控制块 + 原子操作 | 与 shared_ptr 相同 |
| 解引用 | 直接 `*` / `->` | 直接 `*` / `->` | 需先 `lock()` |
| 典型用途 | 工厂返回值、独占资源 | 共享资源、容器存储 | 缓存、打破循环 |

### 5.2 选择策略

```
需要管理堆对象？
├── 只有一个所有者？ → unique_ptr（首选，零开销）
├── 多个所有者？ → shared_ptr
│   └── 其中某些只是"观察"？ → 那些用 weak_ptr
└── 不确定？ → 先用 unique_ptr，需要共享时再改
```

> **核心原则**：默认使用 `unique_ptr`，只有在确实需要共享所有权时才升级为 `shared_ptr`。

## 六、使用注意事项与常见陷阱

### 6.1 不要用裸指针初始化多个 shared_ptr

```cpp
int main() {
    int* raw = new int(42);

    // 严重错误！两个 shared_ptr 各自维护独立的控制块
    // 会 double free → 未定义行为
    // shared_ptr<int> p1(raw);
    // shared_ptr<int> p2(raw);

    // 正确：从同一个 shared_ptr 拷贝
    shared_ptr<int> p1(raw);
    shared_ptr<int> p2 = p1;  // 共享同一个控制块

    return 0;
}
```

### 6.2 避免在构造函数中获取 shared_from_this

```cpp
#include <memory>
using namespace std;

class Widget : public enable_shared_from_this<Widget> {
public:
    // 错误！构造时 shared_ptr 尚未建立控制块
    // shared_ptr<Widget> Create() { return shared_from_this(); }

    // 正确：在对象已被 shared_ptr 管理后调用
    shared_ptr<Widget> GetShared() { return shared_from_this(); }
};

int main() {
    auto w = make_shared<Widget>();
    auto w2 = w->GetShared();  // OK

    return 0;
}
```

### 6.3 注意函数参数传递方式

```cpp
// 按值传递：增加引用计数（有原子操作开销）
void UseShared(shared_ptr<Widget> p);

// 按引用传递：不增加计数（如果不需要延长生命周期）
void ObserveShared(const shared_ptr<Widget>& p);

// 如果只需要使用对象本身，传裸指针或引用即可
void UseWidget(const Widget& w);
```

### 6.4 unique_ptr 与多态

```cpp
#include <iostream>
#include <memory>
#include <vector>
using namespace std;

class Animal {
public:
    virtual void Speak() const = 0;
    virtual ~Animal() = default;  // 多态基类必须有虚析构！
};

class Dog : public Animal {
public:
    void Speak() const override { cout << "Woof!" << endl; }
};

class Cat : public Animal {
public:
    void Speak() const override { cout << "Meow!" << endl; }
};

int main() {
    vector<unique_ptr<Animal>> zoo;
    zoo.push_back(make_unique<Dog>());
    zoo.push_back(make_unique<Cat>());

    for (const auto& animal : zoo) {
        animal->Speak();
    }

    return 0;
}
```

> **切记**：用基类指针管理派生类对象时，基类必须有**虚析构函数**，否则 `delete` 时不会调用派生类的析构。

### 6.5 智能指针与异常安全

```cpp
void Process() {
    auto resource = make_unique<Resource>();  // 获取资源

    DoSomethingThatMayThrow();  // 即使抛异常...

    // ...resource 也会在栈展开时自动释放
}   // unique_ptr 的析构函数保证被调用
```

这正是 RAII + 智能指针的核心价值：**无论函数如何退出（正常返回、异常、提前 return），资源都能被正确释放。**

## 七、总结

### 核心要点回顾

| 知识点 | 关键要点 |
|--------|---------|
| RAII | 构造获取资源，析构释放资源 |
| `unique_ptr` | 独占所有权，零开销，不可拷贝只可移动 |
| `shared_ptr` | 共享所有权，引用计数，有原子操作开销 |
| `weak_ptr` | 不拥有，不增加计数，`lock()` 安全访问 |
| `make_unique` / `make_shared` | 异常安全、代码简洁、`make_shared` 减少一次分配 |
| 循环引用 | 用 `weak_ptr` 打破 |

### 编程建议

1. **永远优先 `unique_ptr`**：它和裸指针一样快，却安全得多。
2. **用 `make_unique` / `make_shared` 创建**：避免裸 `new`。
3. **不要在代码中出现裸 `new` / `delete`**：如果出现了，说明应该用智能指针。
4. **多态基类必须有虚析构**：否则通过基类指针释放时行为未定义。
5. **`shared_ptr` 不是万能的**：原子引用计数有性能开销，不要无脑使用。
6. **明确所有权语义**：函数签名中用 `unique_ptr` 表达"转移"，用 `shared_ptr` 表达"共享"，用裸指针/引用表达"借用"。

智能指针让 C++ 程序员终于可以像使用垃圾回收语言一样安心——但比垃圾回收更高效、更可控。下一篇，我们将探讨支撑智能指针移动语义的底层机制：右值引用与完美转发。
