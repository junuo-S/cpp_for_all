# 05 C++11多线程编程

在 C++11 之前，C++ 标准库没有任何多线程支持，程序员不得不依赖平台特定的 API（Windows 的 CreateThread、POSIX 的 pthread）或第三方库（Boost.Thread）。C++11 将多线程纳入了标准，提供了 `std::thread`、互斥量、条件变量、原子操作和异步任务等一整套工具，让跨平台并发编程成为可能。

---

## 一、多线程概述

### 1.1 进程与线程

- **进程**：操作系统资源分配的基本单位，拥有独立的地址空间
- **线程**：CPU 调度的基本单位，同一进程内的线程共享地址空间和资源

多线程的优势：
- 利用多核 CPU 并行计算
- 提高 I/O 密集型程序的响应性（如 UI 线程不被网络请求阻塞）
- 简化某些问题的建模（如服务器为每个连接分配一个线程）

### 1.2 并发编程的核心挑战

| 问题 | 描述 |
|------|------|
| 数据竞争（Data Race） | 多线程同时读写共享数据，结果不确定 |
| 死锁（Deadlock） | 两个线程互相等待对方释放锁 |
| 活锁（Livelock） | 线程不断让步但都无法推进 |
| 可见性（Visibility） | 一个线程的写入对另一个线程不可见 |

C++11 提供的工具正是为了应对这些挑战。

## 二、std::thread 基本用法

### 2.1 创建线程

```cpp
#include <iostream>
#include <thread>
using namespace std;

void TaskA() {
    cout << "TaskA running in thread: "
         << this_thread::get_id() << endl;
}

void TaskB(int id, const string& msg) {
    cout << "TaskB[" << id << "]: " << msg << endl;
}

int main() {
    cout << "Main thread: " << this_thread::get_id() << endl;

    thread t1(TaskA);
    thread t2(TaskB, 42, "hello");

    t1.join();  // 等待 t1 完成
    t2.join();  // 等待 t2 完成

    cout << "All threads done" << endl;

    return 0;
}
```

### 2.2 join 与 detach

- **join()**：阻塞当前线程，等待目标线程执行完毕
- **detach()**：将线程分离，使其在后台独立运行（不再能 join）

```cpp
#include <iostream>
#include <thread>
#include <chrono>
using namespace std;

void BackgroundWork() {
    this_thread::sleep_for(chrono::seconds(1));
    cout << "Background work done" << endl;
}

int main() {
    thread t(BackgroundWork);

    // 方式 1：join（等待完成）
    // t.join();

    // 方式 2：detach（后台运行）
    t.detach();
    cout << "Main continues without waiting" << endl;

    this_thread::sleep_for(chrono::seconds(2));  // 给后台线程时间完成

    return 0;
}
```

> **重要**：`thread` 对象析构时，如果既没有 join 也没有 detach，程序会调用 `std::terminate()` 直接终止。

### 2.3 线程传参

```cpp
#include <iostream>
#include <thread>
#include <string>
using namespace std;

// 值传递：参数被拷贝到线程内部
void ByValue(int x, string s) {
    cout << "ByValue: " << x << " " << s << endl;
}

// 引用传递：必须用 std::ref / std::cref
void ByReference(int& x) {
    x = 100;
    cout << "ByReference: x = " << x << endl;
}

int main() {
    int val = 0;
    string msg = "world";

    thread t1(ByValue, 42, msg);       // 值拷贝
    thread t2(ByReference, ref(val));  // 引用传递

    t1.join();
    t2.join();

    cout << "val after thread: " << val << endl;  // 100

    return 0;
}
```

> **注意**：`thread` 构造函数默认**拷贝**所有参数。如果需要传引用，必须显式使用 `std::ref()` 或 `std::cref()`。传指针时要确保指向的对象在线程执行期间仍然存活。

### 2.4 移动线程对象

`std::thread` 不可拷贝（一个线程只能被一个 `thread` 对象管理），但可以移动：

```cpp
#include <thread>
using namespace std;

int main() {
    thread t1([]{ /* work */ });

    // thread t2 = t1;       // 编译错误！不可拷贝
    thread t2 = move(t1);    // OK：转移线程所有权

    t2.join();

    return 0;
}
```

## 三、互斥量

### 3.1 数据竞争问题

```cpp
#include <iostream>
#include <thread>
#include <vector>
using namespace std;

int counter = 0;  // 共享变量

void Increment(int n) {
    for (int i = 0; i < n; ++i) {
        ++counter;  // 数据竞争！非原子操作
    }
}

int main() {
    thread t1(Increment, 100000);
    thread t2(Increment, 100000);

    t1.join();
    t2.join();

    // 期望 200000，实际结果不确定（可能小于 200000）
    cout << "counter = " << counter << endl;

    return 0;
}
```

### 3.2 std::mutex

互斥量（Mutex）保证同一时刻只有一个线程能访问受保护的代码段：

```cpp
#include <iostream>
#include <thread>
#include <mutex>
using namespace std;

int counter = 0;
mutex mtx;

void SafeIncrement(int n) {
    for (int i = 0; i < n; ++i) {
        mtx.lock();
        ++counter;
        mtx.unlock();
    }
}

int main() {
    thread t1(SafeIncrement, 100000);
    thread t2(SafeIncrement, 100000);

    t1.join();
    t2.join();

    cout << "counter = " << counter << endl;  // 200000（确定）

    return 0;
}
```

### 3.3 lock_guard：RAII 自动管理锁

手动 `lock()` / `unlock()` 容易出错（忘记解锁、异常路径跳过解锁）。`lock_guard` 利用 RAII 自动管理：

```cpp
void SafeIncrement(int n) {
    for (int i = 0; i < n; ++i) {
        lock_guard<mutex> lock(mtx);  // 构造时加锁
        ++counter;
    }   // 析构时自动解锁（即使抛出异常也能解锁）
}
```

### 3.4 unique_lock：更灵活的锁管理

`unique_lock` 比 `lock_guard` 更灵活，支持延迟加锁、手动解锁/重新加锁、与条件变量配合：

```cpp
#include <iostream>
#include <thread>
#include <mutex>
using namespace std;

mutex mtx;

void FlexibleLock() {
    unique_lock<mutex> lock(mtx, defer_lock);  // 不立即加锁

    // 做一些不需要锁的准备工作...

    lock.lock();    // 手动加锁
    cout << "Critical section" << endl;
    lock.unlock();  // 手动解锁

    // 做其他不需要锁的工作...

    lock.lock();    // 重新加锁
    cout << "Another critical section" << endl;
}   // 析构时自动解锁（如果还持有锁）

int main() {
    thread t(FlexibleLock);
    t.join();
    return 0;
}
```

| 对比项 | `lock_guard` | `unique_lock` |
|--------|-------------|---------------|
| 灵活性 | 构造加锁，析构解锁，不可中途操作 | 可手动 lock/unlock |
| 开销 | 更小 | 略大（维护状态） |
| 条件变量 | 不可用 | 必须使用 |
| 使用场景 | 简单的临界区保护 | 需要灵活控制或配合条件变量 |

## 四、条件变量

### 4.1 等待与通知

条件变量（`condition_variable`）允许线程在某个条件不满足时**阻塞等待**，另一个线程在条件满足时**通知**它继续：

```cpp
#include <iostream>
#include <thread>
#include <mutex>
#include <condition_variable>
#include <queue>
#include <chrono>
using namespace std;

queue<int> taskQueue;
mutex mtx;
condition_variable cv;
bool finished = false;

// 生产者
void Producer() {
    for (int i = 1; i <= 5; ++i) {
        {
            lock_guard<mutex> lock(mtx);
            taskQueue.push(i);
            cout << "Produced: " << i << endl;
        }
        cv.notify_one();  // 通知一个等待的消费者
        this_thread::sleep_for(chrono::milliseconds(100));
    }

    {
        lock_guard<mutex> lock(mtx);
        finished = true;
    }
    cv.notify_all();
}

// 消费者
void Consumer() {
    while (true) {
        unique_lock<mutex> lock(mtx);

        // 等待条件满足（队列为空时阻塞）
        cv.wait(lock, [] {
            return !taskQueue.empty() || finished;
        });

        while (!taskQueue.empty()) {
            int task = taskQueue.front();
            taskQueue.pop();
            cout << "  Consumed: " << task << endl;
        }

        if (finished && taskQueue.empty()) break;
    }
}

int main() {
    thread producer(Producer);
    thread consumer(Consumer);

    producer.join();
    consumer.join();

    cout << "All done" << endl;

    return 0;
}
```

### 4.2 虚假唤醒

`cv.wait()` 可能在没有被 notify 的情况下返回（**虚假唤醒** Spurious Wakeup）。因此必须用谓词（predicate）循环检查条件：

```cpp
// 错误写法：可能因虚假唤醒而在条件未满足时继续
cv.wait(lock);
Process(taskQueue.front());  // 队列可能仍为空！

// 正确写法：带谓词的 wait（内部循环检查）
cv.wait(lock, [] { return !taskQueue.empty(); });
Process(taskQueue.front());  // 安全：队列一定非空
```

## 五、原子操作 std::atomic

### 5.1 无锁同步

对于简单的共享变量操作，互斥量显得过于重量级。`std::atomic` 提供了无锁的原子操作：

```cpp
#include <iostream>
#include <thread>
#include <atomic>
using namespace std;

atomic<int> counter{0};  // 原子变量

void AtomicIncrement(int n) {
    for (int i = 0; i < n; ++i) {
        counter.fetch_add(1, memory_order_relaxed);  // 原子递增
        // 或者简写：++counter;  // 也是原子的
    }
}

int main() {
    thread t1(AtomicIncrement, 100000);
    thread t2(AtomicIncrement, 100000);

    t1.join();
    t2.join();

    cout << "counter = " << counter.load() << endl;  // 200000

    return 0;
}
```

### 5.2 常用原子操作

| 操作 | 说明 |
|------|------|
| `load()` | 原子读取 |
| `store(val)` | 原子写入 |
| `exchange(val)` | 原子交换，返回旧值 |
| `fetch_add(n)` | 原子加，返回旧值 |
| `fetch_sub(n)` | 原子减，返回旧值 |
| `compare_exchange_weak/strong` | CAS 操作 |

### 5.3 内存序（简要）

原子操作的 `memory_order` 参数控制内存可见性：

| 内存序 | 含义 | 性能 |
|--------|------|------|
| `memory_order_relaxed` | 仅保证原子性，不保证顺序 | 最快 |
| `memory_order_acquire` | 读屏障：之后的读写不会被重排到之前 | 中等 |
| `memory_order_release` | 写屏障：之前的读写不会被重排到之后 | 中等 |
| `memory_order_seq_cst` | 顺序一致性（默认）：最强保证 | 最慢 |

> 对于大多数场景，使用默认的 `memory_order_seq_cst` 即可。只有在性能分析确认瓶颈后，才考虑放宽内存序。

## 六、std::future / std::promise / std::async

### 6.1 std::async：最简单的异步

`std::async` 启动一个异步任务，返回 `std::future` 用于获取结果：

```cpp
#include <iostream>
#include <future>
#include <numeric>
#include <vector>
using namespace std;

long long SumRange(const vector<int>& v, int begin, int end) {
    return accumulate(v.begin() + begin, v.begin() + end, 0LL);
}

int main() {
    vector<int> data(1000000);
    for (int i = 0; i < 1000000; ++i) data[i] = i + 1;

    // 启动两个异步任务，并行计算
    auto future1 = async(launch::async, SumRange, cref(data), 0, 500000);
    auto future2 = async(launch::async, SumRange, cref(data), 500000, 1000000);

    // 获取结果（阻塞等待）
    long long sum = future1.get() + future2.get();

    cout << "Sum = " << sum << endl;  // 500000500000

    return 0;
}
```

`launch` 策略：
- `launch::async`：强制在新线程中执行
- `launch::deferred`：延迟执行（调用 `get()` 时才在当前线程执行）
- `launch::async | launch::deferred`（默认）：由实现决定

### 6.2 std::promise 与 std::future

`promise` / `future` 对提供了一种线程间"一次性"通信机制：

```cpp
#include <iostream>
#include <thread>
#include <future>
using namespace std;

void Compute(promise<int>& prom, int x) {
    this_thread::sleep_for(chrono::seconds(1));  // 模拟耗时计算
    prom.set_value(x * x);  // 设置结果
}

int main() {
    promise<int> prom;
    future<int> fut = prom.get_future();

    thread t(Compute, ref(prom), 7);

    cout << "Waiting for result..." << endl;
    int result = fut.get();  // 阻塞，直到 promise 设置值
    cout << "Result: " << result << endl;  // 49

    t.join();

    return 0;
}
```

### 6.3 std::packaged_task

`packaged_task` 将可调用对象包装起来，使其返回值可以通过 `future` 获取：

```cpp
#include <iostream>
#include <future>
#include <functional>
using namespace std;

int Add(int a, int b) { return a + b; }

int main() {
    packaged_task<int(int, int)> task(Add);
    future<int> fut = task.get_future();

    thread t(move(task), 3, 4);  // packaged_task 不可拷贝，必须 move

    cout << "Result: " << fut.get() << endl;  // 7

    t.join();

    return 0;
}
```

### 6.4 三者对比

| 工具 | 用途 | 特点 |
|------|------|------|
| `std::async` | 启动异步任务并获取结果 | 最简单，一行搞定 |
| `promise` / `future` | 线程间一次性传值 | 灵活，可跨线程传递 |
| `packaged_task` | 包装可调用对象为异步任务 | 可存入队列，延迟执行 |

## 七、线程安全设计原则与常见陷阱

### 7.1 设计原则

1. **最小化共享**：能不共享就不共享。线程局部变量（`thread_local`）或消息传递优于共享内存。
2. **最小化临界区**：锁的持有时间越短，并发度越高。
3. **避免嵌套锁**：如果必须获取多把锁，所有线程按**相同顺序**获取，防止死锁。
4. **优先使用高级抽象**：`async`、线程池、并发容器优于手动管理线程和锁。

### 7.2 死锁示例与预防

```cpp
#include <iostream>
#include <thread>
#include <mutex>
using namespace std;

mutex mtx1, mtx2;

// 死锁！两个线程以不同顺序获取锁
void ThreadA() {
    lock_guard<mutex> l1(mtx1);
    this_thread::sleep_for(chrono::milliseconds(10));
    lock_guard<mutex> l2(mtx2);  // 等待 ThreadB 释放 mtx2
    cout << "ThreadA done" << endl;
}

void ThreadB() {
    lock_guard<mutex> l2(mtx2);
    lock_guard<mutex> l1(mtx1);  // 等待 ThreadA 释放 mtx1
    cout << "ThreadB done" << endl;
}

// 解决方案 1：统一加锁顺序
// 解决方案 2：使用 std::lock 同时获取多把锁
void SafeThread() {
    lock(mtx1, mtx2);  // 原子地获取两把锁（内部避免死锁）
    lock_guard<mutex> l1(mtx1, adopt_lock);
    lock_guard<mutex> l2(mtx2, adopt_lock);
    cout << "Safe" << endl;
}
```

### 7.3 常见陷阱清单

| 陷阱 | 说明 |
|------|------|
| 忘记 join/detach | `thread` 析构时调用 `terminate()` |
| 悬垂引用传参 | 线程引用的局部变量已销毁 |
| 在锁内做 I/O | 严重降低并发性能 |
| 对非 POD 类型用 `atomic` | `atomic<T>` 要求 T 是 trivially copyable |
| 条件变量不用谓词 | 虚假唤醒导致逻辑错误 |
| 单例的双重检查锁 | 需要 `atomic` + 内存屏障（C++11 的 `static` 局部变量已线程安全） |

### 7.4 thread_local

C++11 的 `thread_local` 让每个线程拥有变量的独立副本，完全避免竞争：

```cpp
#include <iostream>
#include <thread>
using namespace std;

thread_local int localCounter = 0;  // 每个线程独立的副本

void Work() {
    for (int i = 0; i < 1000; ++i) {
        ++localCounter;  // 无竞争，无需加锁
    }
    cout << "Thread " << this_thread::get_id()
         << ": localCounter = " << localCounter << endl;
}

int main() {
    thread t1(Work);
    thread t2(Work);

    t1.join();
    t2.join();

    cout << "Main: localCounter = " << localCounter << endl;  // 0（主线程自己的）

    return 0;
}
```

## 八、总结

### 核心要点回顾

| 知识点 | 关键要点 |
|--------|---------|
| `std::thread` | 创建线程，必须 join 或 detach |
| 传参 | 默认拷贝，引用需 `std::ref` |
| `mutex` + `lock_guard` | RAII 保护临界区 |
| `unique_lock` | 灵活锁管理，条件变量必须搭配 |
| `condition_variable` | 等待/通知模式，必须用谓词防虚假唤醒 |
| `std::atomic` | 无锁原子操作，适合简单计数器 |
| `async` / `future` | 最简单的异步任务与结果获取 |
| `promise` | 线程间一次性通信 |
| `thread_local` | 线程私有变量，避免共享 |

### 编程建议

1. **能用高级抽象就不用低级原语**：优先 `async`、线程池，而非手动 `thread` + `mutex`。
2. **减少共享状态**：设计时尽量让线程各自处理独立数据。
3. **锁的粒度要恰当**：太粗影响并发，太细增加复杂度和开销。
4. **永远不要忽略线程生命周期**：确保线程访问的数据在线程结束前有效。
5. **测试并发 bug 很困难**：写代码时就要从设计上避免竞争，而非依赖测试发现。

多线程编程是 C++ 中最复杂也最强大的领域之一。C++11 的标准线程库为我们提供了坚实的基础设施。下一篇，我们将把目光投向 C++20，探索协程这一全新的并发编程范式。
